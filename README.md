## Как проверить решение

Откройте вкладку **Terminal** в IDEA. Выполняйте команды из корня проекта — папки, в которой лежат этот README и `gradlew`.
Ниже пример для задачи `task01`. Для другой задачи замените номер в пути и сообщении коммита.

### 1. Посмотрите изменения

```shell
git status
git diff
```

`status` показывает текущую ветку и изменённые файлы, `diff` — изменения внутри файлов.
Работаем в ветке `main` своего форка. Проверить адрес репозитория можно командой:

```shell
git remote -v
```

У `origin` должен быть адрес **вашего форка**, с вашим ником на GitHub.

### 2. Подготовьте решение к коммиту

```shell
git add task01/src/main/kotlin
git diff --staged
```

`add` добавляет файлы решения в будущий коммит. `diff --staged` показывает, что именно в него попадёт.
Проверьте, что подготовлены только ваши изменения решения.

### 3. Создайте коммит

```shell
git commit -m "Solve task01"
```

Коммит сохраняет подготовленные изменения **на вашем компьютере**. Сообщение кратко описывает, что вы сделали.
Например, для исправления: `git commit -m "Fix task01 boundary check"`.

Если Git впервые просит указать автора, выполните команды, подставив своё имя и email, затем повторите commit:

```shell
git config user.name "Ваше имя"
git config user.email "your-email@example.com"
```

Эти настройки действуют только в текущем репозитории.

### 4. Отправьте код на GitHub

Перед первым push откройте **Actions** в своём форке и включите workflows кнопкой **I understand my workflows, go ahead and enable them**, если она отображается.

```shell
git push -u origin main
```

`push` отправляет коммиты в ваш форк. Параметр `-u` запоминает, куда отправлять ветку; в следующие разы достаточно `git push`.
Если терминал запросит авторизацию GitHub, а вход не получится, позовите преподавателя.

### 5. Посмотрите результат

На GitHub откройте **свой форк → Actions → Проверка заданий → последний запуск** и дождитесь завершения.
Выберите нужную задачу → **Показать результаты**: здесь перечислены проверки и причины ошибок.

Смотрите на результат своей задачи: общий запуск может быть красным из-за остальных, ещё не решённых задач.

После исправления снова выполните:

```shell
git add task01/src/main/kotlin
git commit -m "Fix task01"
git push
```

Каждый новый push запускает проверку заново.
