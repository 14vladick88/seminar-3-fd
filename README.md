# Семинар 3 · Kotlin: от условий к объектам

90 минут. Решаем задачи в IDEA, отправляем код в свой форк и смотрим автоматические проверки.
Основная часть — задачи 01–04; задача 05 дополнительная. Первая цель — решить 01 и увидеть зелёную проверку именно этой задачи.

## Быстрый старт

1. Нажмите **Fork** в [репозитории семинара](https://github.com/Slava-ne-Merlow/seminar-3-fd) → **Create fork**.
2. В **своём** форке откройте **Actions** → **I understand my workflows, go ahead and enable them**, если GitHub показывает эту кнопку. Это нужно сделать один раз, до первого push.
3. Скопируйте HTTPS-ссылку через **Code** в своём форке. В IDEA выберите **Get from VCS / Clone Repository** (или **File → New → Project from Version Control**) и вставьте эту ссылку.
4. Откройте корневую папку проекта как Gradle-проект и дождитесь синхронизации. Отдельно устанавливать Gradle или Kotlin не нужно: проект использует Gradle Wrapper.
5. Для проекта выберите **JDK 17**. Если его нет: **File → Project Structure → SDK → Download JDK**, версия 17 (например, Temurin). В **Settings → Build, Execution, Deployment → Build Tools → Gradle** выберите этот же JDK в **Gradle JVM**, а Gradle distribution — **Wrapper**. На macOS настройки могут называться Preferences.
6. Откройте `task01/src/test/kotlin/seminar/task01/Task01Test.kt` и нажмите зелёный треугольник возле класса. Первый запуск скачает зависимости и может занять несколько минут.

**На старте проверки красные:** в заготовках стоят `TODO(...)`, которые выбрасывают `NotImplementedError`.
Это ожидаемый результат запуска, а не неисправность установки. Ошибка компиляции или скачивания зависимостей — другая ситуация; смотрите текст ошибки.

## Как решать

Читайте README задачи, затем изменяйте только её файлы в `src/main/kotlin`.
Сохраняйте имена функций, классов, пакетов и типы параметров: тесты обращаются к ним напрямую.
Удалите `TODO(...)` и напишите реализацию. Ввод через `readln` и `main` не нужны — тесты сами вызывают ваш код.

Тесты открыты: их можно читать, чтобы понять пример или ошибку. Для сдачи не изменяйте тесты, Gradle и workflow.
Задачи независимы; незавершённая task05 не мешает запускать task01.

В IDEA можно запускать тестовый класс нужной задачи кнопкой ▶. Если IDEA предлагает компилировать весь проект, выберите **Run tests using: Gradle** в настройках Gradle или команду ниже.

Через терминал IDEA (из корня проекта), macOS / Linux:

```shell
./gradlew :task01:test
```

Windows PowerShell:

```powershell
.\gradlew.bat :task01:test
```

Замените `task01` на номер нужной задачи. Все задачи, продолжая после ошибок:

```shell
./gradlew test --continue
```

В Windows: `.\gradlew.bat test --continue`.
Локальный подробный отчёт: `task01/build/reports/tests/test/index.html`.

## Commit → Push → результат

1. В IDEA откройте **Commit**, выберите изменённые файлы решения и укажите сообщение, например `Solve task01`.
2. Сделайте **Commit**, затем **Push** (меню Git). Проверьте, что адрес назначения — ваш форк.
3. На GitHub откройте **свой форк → Actions → Проверка заданий → последний запуск**. Сверьте короткий хеш коммита с отправленным.
4. В Summary появятся результаты, а слева — пять отдельных проверок. Откройте нужную → **Проверить решение**: там названия тестов и причины ошибок.
5. Если нужен подробный отчёт, скачайте внизу страницы запуска `report-task01`, распакуйте архив и откройте `index.html` внутри папки отчёта. Отчёты хранятся 14 дней.

В целом запуск остаётся красным, пока есть нерешённые задачи, включая дополнительную. Ориентируйтесь на отдельные проверки: зелёные 01–04 означают, что основная часть выполнена.
Новый push запускает новую проверку; незаконченная проверка предыдущего коммита в той же ветке отменяется.
Если отправили код до включения Actions, после включения выберите workflow → **Run workflow**.

Для сдачи пришлите преподавателю **ссылку на свой форк и ссылку на последний запуск Actions**, укажите выполненные задачи.
Работаем в `main` своего форка. PR в репозиторий преподавателя не требуется.

## Если что-то не получается

- **Gradle не видит Java 17:** проверьте JDK проекта и Gradle JVM, затем нажмите Reload All Gradle Projects.
- **Долго загружаются зависимости:** первый запуск требует интернета. Не запускайте несколько синхронизаций одновременно. При ошибке сети сохраните её текст и позовите преподавателя.
- **`Permission denied: ./gradlew`:** выполните `bash ./gradlew :task01:test`. На Windows используйте `gradlew.bat`.
- **Actions пустая:** убедитесь, что это ваш форк, включите workflows и сделайте push или Run workflow.
- **Push отклонён:** проверьте владельца репозитория в Git → Manage Remotes; затем авторизацию GitHub в IDEA. Пароль от сайта GitHub не подходит как пароль для HTTPS Git; используйте вход через IDEA.
- **`Compilation error`:** исправьте синтаксис и сигнатуры в указанном файле. До тестов выполнение ещё не дошло.
- **`Expected … but was …`:** сравните ожидаемый и полученный результат, откройте названный тест.
- **Нет отчёта:** при ошибке компиляции тесты не стартуют, поэтому HTML-отчёта ещё нет; читайте лог шага.
