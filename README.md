## Работа над решением

Работаем в `main` своего форка. Создание форка и открытие проекта разберём вместе на занятии.
Для проекта используем **JDK 26** — ту же версию, что установили на занятии.
В своём форке один раз откройте **Actions** и включите workflows кнопкой **I understand my workflows, go ahead and enable them**, если она отображается.

Прочитайте условие задачи и откройте указанный в нём файл в `src/main/kotlin`.
Замените `TODO(...)` своей реализацией. Сохраните имена функций, классов, пакетов и типы параметров — проверки обращаются к ним напрямую.
Ввод через `readln` и функция `main` не нужны: проверка сама передаёт данные вашему коду.

Меняйте только файлы решения. Тесты можно читать, но изменять тесты, настройки сборки и workflow для сдачи не нужно.
Задачи независимы: ошибка в одной не мешает проверке остальных.

## Как проверить решение

1. В IDEA откройте **Commit**, выберите изменённые файлы и напишите сообщение, например `Solve task01`.
2. Сделайте **Commit**, затем **Push**. Проверьте, что отправляете код в свой форк.
3. На GitHub откройте **свой форк → Actions → Проверка заданий → последний запуск**. Выберите запуск своего последнего коммита и дождитесь завершения.
4. Откройте нужную задачу → **Показать результаты**. Здесь перечислены проверки и причины ошибок. Та же сводка доступна на странице **Summary** запуска.
5. Исправьте решение и повторите **commit → push**.

На старте проверки красные: заготовки ещё не реализованы. Смотрите на результат конкретной задачи — общий запуск остаётся красным, пока есть нерешённые задачи, в том числе дополнительные.
Итог задачи определяется шагом **Показать результаты**. Зелёный шаг **Проверить решение** означает, что запуск завершён и его результат передан дальше, а не что решение верное.
Зелёные проверки 01–03 означают, что основная часть выполнена.

## Как читать результат

- **В решении остался TODO** — замените заглушку своим кодом.
- **`expected … but was …`** — результат отличается от ожидаемого. Посмотрите название проверки и соответствующий тест.
- **Тесты не запустились** — откройте шаг **Проверить решение**. Если там ошибка компиляции, исправьте синтаксис или сигнатуру в указанном файле.
- **Пропущено** — эта проверка не выполнялась; это не успешный результат.
- **Все проверки задачи пройдены** — задача прошла автопроверку.

Если запуск не появился, проверьте, что выполнен push и включены workflows в Actions своего форка. После включения можно выбрать **Run workflow** для ручного запуска.
При новом push незавершённая проверка предыдущего коммита в той же ветке отменяется — открывайте самый свежий запуск.

Подробный отчёт можно скачать на странице запуска в разделе **Artifacts**: `report-task01` и аналогичные архивы для других задач. Отчёты хранятся 14 дней.
