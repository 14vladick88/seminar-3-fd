# 05. Групповая поездка · дополнительно

Одна поездка может оплачиваться сразу за нескольких пассажиров. Есть карта с ограниченным остатком и безлимитный проездной. После успешной оплаты сервис отправляет одно уведомление за всю группу.

Создайте все интерфейсы и классы самостоятельно в файле [TripService.kt](src/main/kotlin/seminar/task05/TripService.kt).

## Проездные

Интерфейс `TravelPass` объявляет метод `pay(passengers: Int): Boolean`.
Он пытается оплатить поездку за указанное число пассажиров. Количество должно быть положительным, иначе `IllegalArgumentException`.

Реализуйте два класса:

- `TravelCard(initialTrips: Int)` реализует `TravelPass`. Начальный остаток может быть нулевым, но не отрицательным; иначе `IllegalArgumentException`. Свойство `remainingTrips: Int` доступно снаружи только для чтения. Если поездок хватает на всю группу, `pay` списывает нужное количество и возвращает `true`. Если не хватает — возвращает `false` и **сохраняет весь остаток**. Некорректное количество пассажиров тоже не должно менять остаток.
- `UnlimitedPass()` реализует `TravelPass`. Оплачивает любое положительное число пассажиров и возвращает `true`. Отрицательное и нулевое количество запрещены, как и у обычной карты.

Разные карты имеют независимые остатки. В этой задаче метод пополнения не нужен.

## Уведомитель и сервис

Интерфейс `Notifier` объявляет метод `send(message: String): Unit`.
Реализацию уведомителя передаёт вызывающий код; писать консольный уведомитель для сдачи не требуется.

Класс `TripService(notifier: Notifier)` получает уведомитель при создании и предоставляет метод `travel(pass: TravelPass, passengers: Int): Boolean`.

Требования к методу:

- Неположительное количество пассажиров вызывает `IllegalArgumentException`. В этом случае нельзя обращаться ни к проездному, ни к уведомителю.
- Для положительного количества вызывается `pay` переданного проездного ровно один раз с размером всей группы.
- При отказе возвращается `false`, уведомлений нет.
- При успехе отправляется ровно одно сообщение `Поездка оплачена. Пассажиров: N`, где N — размер группы, и возвращается `true`.
- Сообщение отправляется после оплаты. Считайте, что уведомитель работает без ошибок.

Сервис должен работать с любыми реализациями `TravelPass` и `Notifier`, включая неизвестные ему классы. Не проверяйте конкретный тип проездного и не создавайте замену переданным объектам внутри сервиса. Один сервис можно использовать для нескольких последовательных поездок с разными проездными.

В тестах начальный остаток и положительное количество пассажиров не превышают 100 000.

## Пример

На карте 7 поездок. Попытка оплатить группу из 8 пассажиров отклоняется: на карте по-прежнему 7 поездок, сообщения нет.
Затем группа из 4 пассажиров успешно оплачивается: остаётся 3 поездки, отправляется `Поездка оплачена. Пассажиров: 4`.
